## 核心设计思路与关键取舍

### 取舍 1：bob 无 OA 权限时选择「只读完成 + tool.skipped」而非硬 403

当 bob 提交需要 OA 写入的任务时，系统仍创建 run 并完成 ERP/BI/知识库/供应商风险分析；OA 步骤写入 `tool.skipped` 和 deny audit，最终 run 为 `completed`，且 `result.recommended_action = "replenishment_recommended_no_write_permission"`。

这样可以保留只读分析能力，同时保证无权限用户不会产生 OA 草稿副作用。

### 取舍 2：Planner 保持纯函数，权限矩阵集中在 Executor

Planner 只负责 SKU 提取、意图识别和确定性工具计划生成。工具权限统一由 Executor 中的 `TOOL_PERMISSIONS` 矩阵裁决，避免安全逻辑分散。

### 取舍 3：脱敏采用键级删除，而不是只替换 value

验收会全文扫描 `vendor_secret`、`unit_cost_usd` 等字符串，因此敏感 key 本身也不能进入 API、事件或审计日志。实现中对敏感字段采用 dict 整项删除。

脱敏边界包括：

- `ToolRegistry.call` 源头脱敏
- Executor / Worker 出口脱敏
- `insert_run_event` / `insert_audit_log` DB 写入口兜底脱敏

### 取舍 4：补充对象级权限

仅拥有 `tasks:run` 不代表可以运行他人创建的 task。当前实现要求 task 创建者或 `admin:read` 用户才能触发 run，避免通过 `requested_by` 绕过 run/events 可见性。

## 防写死策略

- SKU 使用正则提取，不写死 `SKU-001` / `SKU-002`
- fixtures 路径、DB 路径读取 `ASSESSMENT_FIXTURES_DIR` / `ASSESSMENT_DB_PATH`
- OA 审批阈值从 `oa_rules.json` 读取，不写死 30 / 5000
- 权限判断基于用户 permissions，不基于用户名
- RAG 根据 chunk permission 过滤，不写死公开样例文档内容

## 已知风险

- 隐藏 SKU 如果使用纯数字或小写格式，当前 SKU 正则可能不匹配；此时会进入可解释 failed
- 注入文本如果跨行拆分，RAG 行级过滤可能漏掉部分变体；任务创建阶段的 `detect_prompt_injection` 提供第二道防线
- bob 明确要求 OA 草稿但无写权限时，当前策略为只读完成 + skipped；如果评审预期该路径 failed，需要调整 skippable 策略
